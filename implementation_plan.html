LagCheck 自動化腳本更新規劃檔

同步修訂 lagcheck_auto.py、index.html 與 test.html 的 JSON 匯出及解析邏輯

1. 問題分析與修訂目標 (Goal)

經過比對最新版 index.html 的 URL Automation Engine 與 JSON 匯出機制，發現 lagcheck_auto.py 有以下需要調整與優化之處：

  • 綜合評級 (Grade) 顯示 N/A 修正：index.html 在匯出 JSON (exportJson) 時，未將 gradeFor(stats) 計算出的評級資訊寫入 JSON Payload 的 stats 物件，導致 Python 腳本讀取 stats.get('grade') 時皆回應 N/A。
  • P50 中位數欄位提取錯誤：Python 腳本原為 stats.get('current', stats.get('p50'))，會優先拿單次最新延遲 (current) 替代 P50，應調整為優先取 p50。
  • 測試環境與目標網址彈性 (Env Support)：現行 Python 腳本硬編碼指向 test.html。新增 CLI 參數 --env (staging / prod / local) 或 --page-url，讓使用者可切換測試正式版、測試版或本機 Web 伺服器。
  • 雙軌發布同步 (Dual-track Sync)：修改 index.html 的 JSON 匯出邏輯後，同步複製覆蓋至 test.html，維護專案雙軌發布規範。

2. 變更細節與代碼比對 (Proposed Changes)

[MODIFY] index.html & test.html

在 JSON Payload 產生處 (exportJson 與 triggerAutoExportOrWebhook)，將計算後的 grade, score, gradeLabel 自動併入 stats 匯出資料中：

// 前後代碼對比 (index.html / test.html)
- const payload = customPayload || {
-   timestamp: new Date().toISOString(),
-   version: APP_VERSION,
-   clientInfo: state.netTraceInfo,
-   settings: state.settings,
-   stats: currentStats(),
-   samples: state.samples
- };

+ const statsObj = currentStats();
+ const gradeObj = gradeFor(statsObj);
+ const payload = customPayload || {
+   timestamp: new Date().toISOString(),
+   version: APP_VERSION,
+   clientInfo: state.netTraceInfo,
+   settings: state.settings,
+   stats: {
+     ...statsObj,
+     grade: gradeObj.grade,
+     score: gradeObj.score,
+     gradeLabel: gradeObj.label
+   },
+   samples: state.samples
+ };

[MODIFY] lagcheck_auto.py

1. 新增 --env 與 --page-url 參數支援環境選擇：

+     "prod": "https://davislinyd.github.io/LagCheck/",
+     "local": "http://localhost:8000/test.html"
+ }

2. 修正 parse_and_print_report 之 P50 取值邏輯：

- print(f"  • 中位數延遲 (P50)     : {stats.get('current', stats.get('p50', '—'))} ms")
+ p50_val = stats.get('p50')
+ if p50_val is None: p50_val = stats.get('current', '—')
+ print(f"  • 中位數延遲 (P50)     : {p50_val} ms")
